BIA CONTROL DE CONTENEDORES - PWA + SUPABASE
================================================

Este paquete contiene la aplicación web progresiva completa y lista para
publicarse como sitio estático.

ARCHIVOS PRINCIPALES
--------------------
- index.html: entrada de la aplicación.
- _next/: archivos JavaScript y CSS compilados. No cambie su estructura.
- manifest.webmanifest: configuración de instalación de la PWA.
- sw.js: servicio para instalación y funcionamiento sin conexión.
- pwa-icon-192.png y pwa-icon-512.png: iconos de la aplicación.
- brand/: logotipo y recursos de BIA Honduras.
- docs/Guia_Configuracion_Supabase_BIA.pdf: guía de configuración.
- supabase-setup.sql: tablas, permisos, almacenamiento y políticas de Supabase.

ANTES DE PUBLICAR
-----------------
1. Abra su proyecto de Supabase.
2. Entre a SQL Editor.
3. Copie y ejecute todo el contenido de supabase-setup.sql.
4. Revise que Authentication esté habilitado y cree los usuarios que usarán
   la aplicación.

PUBLICAR EN SUPABASE STORAGE
----------------------------
Supabase es principalmente el backend de la aplicación. Storage permite alojar
estos archivos, aunque para una PWA de producción suele ser más confiable usar
un hosting estático y dejar Supabase para la base de datos, usuarios y fotos.

Si desea usar Supabase Storage:

1. En Storage, cree un bucket público, por ejemplo: bia-pwa.
2. Suba EL CONTENIDO de este paquete, no la carpeta contenedora.
3. Conserve exactamente las carpetas _next, brand y docs.
4. Compruebe los tipos de contenido al subir:
   .html          text/html
   .js            application/javascript
   .css           text/css
   .webmanifest   application/manifest+json
   .json          application/json
   .svg           image/svg+xml
   .png           image/png
   .pdf           application/pdf
   .sql y .txt    text/plain
5. Abra la URL pública completa que termine en /index.html. No use solamente
   la URL del bucket o de la carpeta.
6. En Configuración dentro de la aplicación, capture:
   - URL del proyecto Supabase: https://SU-PROYECTO.supabase.co
   - Clave pública anon o publishable. Nunca use service_role en el navegador.
7. En Authentication > URL Configuration de Supabase agregue la URL pública
   final de index.html y/o la carpeta como Site URL y Redirect URL permitida.

IMPORTANTE
----------
- Todos los archivos deben estar publicados por HTTPS para poder instalar la
  PWA y registrar el service worker.
- No abra index.html con doble clic mediante una dirección file://.
- No cambie nombres ni mueva archivos después de compilarlos.
- El módulo de productos busca por codigo o codigo_barra en la tabla codigo y
  completa automáticamente la columna descripcion.
- El script supabase-setup.sql incluye los permisos necesarios para consultar
  esa tabla cuando ya existe en su proyecto.
